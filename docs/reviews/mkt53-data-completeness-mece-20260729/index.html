先把真相说清楚

本轮结果来自 2026-08-09 当前源码、source registry、本地一致性审计、深度 claim 扫描和 45 路由桌面/移动 sweep。没有调用受限连接器，也没有把样例数据升级成事实。

  • 855 条数字/导出声明为低风险；0 high、0 medium、0 unsupported。
  • 45 条业务路由均有 source mapping 和唯一 target metric contract；合同校验 0 invalid。

仍然不完整

  • 14 个 L0、10 个合成示例、2 个 L2 fixture 不能代表真实业务接入。

核心判断：继续填静态数字只会制造更精致的假象。正确顺序是先定义决策与指标合同，再补授权快照/人工证据，最后由同一合同驱动页面、CSV 和报告。

两层 MECE 模型

路由按一个主业务域归类；每页再按完整数据生命周期检查。业务域之间不重复，生命周期门之间不能互相替代。

8 个互斥业务域

导航；市场；竞争；用户/VOC；行业；自我经营；AI；报告/数据治理。别名路由按目标职责归类，而不是按当前复用组件归类。

7 个完整性门

决策问题 → 指标合同 → 采集合同 → 质量合同 → 证据审批 → 展示导出 → 运行责任。七门全过才是 decision-ready。

完整解决方案

保留静态前端和 fail-closed 优势，在其后增加版本化数据与审批链，而不是一次性重写。

公开事实层

官方/公开报告只在 claim scope 内展示；保存 URL、标题、窗口、hash 和引用。403/付费墙改走人工复核，不伪装自动采集。

内部只读层

ERP/CRM/BI 使用不可变授权快照，默认 private/internal；每个 proxy 明确禁止替代的 GMV、份额或市场分母。

连接器与人工研究层

Amazon、社媒、YouTube、VOC、贸易数据先过 owner intake；访谈/法规/美学保存 consent、样本、编码、证据 hash 与 reviewer。

模型与报告层

保存 dataset snapshot、model、prompt hash、evaluation、cost、human review、citation map、approval 与 revocation。

统一链路

决策问题 → 指标合同 → 授权/来源合同 → immutable snapshot + hash → 质量与对账 → owner review → page adapter → gate / CSV / report → freshness / rollback

数据完成

产品完成

页面、CSV、报告同口径；example 不进 KPI；freshness、SLA、失败和回滚可见；别名路由职责一致。
